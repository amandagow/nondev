Collaboration is central to GitHub.

In this unit, we focus on **issues** and **discussions**- two tools that help teams coordinate work and communicate clearly.

## Issues

A **GitHub Issue** is a tracked work item. Issues are used to track ideas, feedback, tasks, bugs, or follow-up actions.

Think of an issue as a shared, trackable record of work that can be assigned, prioritized, and discussed. 

Issues help business and technical teams stay aligned by making work visible:
- what needs to be done
- who owns it
- when it's due
- current status

### Creating an issue from a repository

1. On GitHub.com, go to the the repository.
2. Select **Issues**.

   :::image type="content" source="../media/issues-tab.png" alt-text="Screenshot showing the top portion of the main page of a repository with the Issues section highlighted." border="false":::

3. Select **New issue**. 
4. If templates are shown, choose the best match (or select **Blank Issue** if needed). 

   :::image type="content" source="../media/open-a-blank-issue.png" alt-text="A screenshot of the issue templates menu, with the Open a blank issue option highlighted." border="false":::

5. Enter a title for your issue.
6. Add a description with context, expected outcome, and any deadlines or constraints.
7. (Optional, if you have permission) assign an owner, add labels, connect to a project, or set a milestone.
8. When you're finished, select **Submit new issue**.

Use labels, mentions, and templates to keep issue quality and visibility high.

---

Some conversations are better handled in Discussions rather than Issues.
Use Discussions for questions, brainstorming, announcements, and community-style conversations.
## Discussions

A Discussion is for open conversation that may not yet require a tracked work item.
Use discussions when you want to ask questions, gather input, or share updates.
### Issues vs. Discussions (Quick Guide)
- Use an **Issue** when work needs tracking and ownership.
- Use a **Discussion** when the goal is conversation or idea-sharing.
- If a discussion becomes actionable, convert it into an issue.

### Enabling a discussion in your repository

Repository owners (and users with Write access) can enable Discussions.

1. Go to the repository. 
2. Select **Settings**
   :::image type="content" source="../media/settings-tab.png" alt-text="A screenshot of the top portion of the main page of a repository with the Settings section highlighted." border="false":::

3. In **Features**, find **Discussions**, and select **Setup discussions**.

   :::image type="content" source="../media/set-up-discussion.png" alt-text="A screenshot of the Discussions box with the green Setup discussion button highlighted." border="false":::

4. Under **Start a new discussion**, update the welcome content.
5. Select **Start discussion**.

You're now ready to create a new discussion.

### Create a new discussion

Any signed-in user who can view the repository can generally create a discussion there.

1. Go to the repository (or organization) where you want to start a discussion.

2. Select **Discussions**.

   :::image type="content" source="../media/discussions-tab.png" alt-text="A screenshot of the top portion of the main page of a repository with the Discussions section highlighted." border="false":::

3. Select **New discussion**.

4. Choose a category and select **Get started**. 
   :::image type="content" source="../media/announcements.png" alt-text="A screenshot of the select a discussion category menu selection, with the top option Announcements and the get started button highlighted." border="false":::

5. Add a title and discussion content.

   :::image type="content" source="../media/start-a-new-discussion.png" alt-text="A screenshot of starting a new discussion page with the Discussion title box and content box empty." border="false":::

6. Select **Start discussion**.

### Discussion Categories
Each discussion category includes a unique name, emoji, and description to clarify its purpose. 

| **Category** | **Purpose** | **Format** |
|----------|----------|----------|
| :mega: Announcements | Updates and news from project maintainers | Announcement |
| :hash: General | Anything and everything relevant to the project | Open-ended discussion |
| :bulb: Ideas | Ideas to change or improve the project | Open-ended discussion |
| :ballot_box: Polls | Polls with multiple options for the community to vote for and discuss | Polls |
| :pray: Q&A | Questions for the community to answer, with a question/answer format | Question and Answer |
| :raised_hands: Show and tell | Creations, experiments, or tests relevant to the project | Open-ended discussion |

Maintainers can pin important discussions for better visibility.

### Useful collaboration actions in discussions

#### Marking a comment as an answer (Q&A categories)

1. Open the discussion.
2. Find the best response.
3. Select **Mark as answer**.

This highlights the solution for future readers.

### Reference a discussion in an issue

If conversation turns into actionable work.

1. Open the discussion.
2. Select the **`...`** menu(top-right).
3. Select **Reference in new issue**.
4. Confirm and create the issue.

This keeps track of actionable work that originates from community conversations.

### Pin a discussion

To keep key topics visible:

1. Open the discussion.
2. Select the **`...`** menu.
3. Select **Pin discussion**.

Pinned discussions are helpful for highlighting announcements, important questions, or ongoing topics the community should notice.
